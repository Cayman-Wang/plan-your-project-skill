# 项目接续协议：匿名场景静态评估

日期：2026-09-22。

下列原有八场景部分保留当时的静态评估记录。2026-09-23 的修复回归及两次实际新上下文执行见文末；两者的范围和证据不混用。

## 方法与结论边界

输入为 `behavior_evals.json` 中固定的 8 个匿名场景及 40 条可观察标准。基线为公开仓库提交 [`120dba1d006e959dc456f007b0f9defcf9da39dd`](https://github.com/Cayman-Wang/plan-your-project-skill/tree/120dba1d006e959dc456f007b0f9defcf9da39dd)；新版为本次升级候选。评估者分别读取两版技能和相关协议，推演其要求的下一步，并与实际 CLI 集成测试区分报告。

**这是协议推演和静态评估，不是真实多 AI 盲测，不是成功率实验。** 没有把 8 个场景交给全新模型会话执行，没有随机化顺序，没有测量模型遵从率；评估者知道升级目标，也看过实现。场景内的项目与结果均为匿名测试输入，未运行其中的虚构实验。CLI 测试只在临时目录验证实际工具行为。

对比采用各版协议的原生有效记录格式，考察相同项目事实下的接续语义；不把新版格式交给旧版后产生的解析失败计为旧版行为失败。真实 v2 → v2.1 转换另外通过显式迁移测试检查。

“明确支持”表示协议直接给出要求，且没有发现相反规则；“部分支持”表示已有通用原则，但具体接续机制或边界未规定；“直接冲突”表示存在会把下一步带向相反结果的明确文字。用户显式要求仍优先于技能，基线冲突并不意味着所有遵守指令优先级的代理必然失败。

## 1. 落后 STATUS 与新授权工作

Fixture：`stale_status_newer_authorized_work`。

基线 `SKILL.md:15` 已要求区分 STATUS 记录、容易取得的真实证据和未知，因此不能说旧版完全不核实状态。但 `SKILL.md:34` 要求交接给执行 skill 后停止；`file_contract_zh.md:66` 又把 `must_read` 称为唯一后续读取清单，缺少主动对照更晚执行记录的完整流程。

新版的预期下一步是：读取入口与必要资料，核对较新缓存报告及产物，明确旧 M2 状态和已授权诊断的差别；只继续本次已授权缓存比较，保留科研 gate 待审，并在授权范围内更新接续入口。不重复采集、训练或索取同一授权。

依据：新版 `SKILL.md:15-16,30,34,40`；`references/progress_protocol_zh.md:5-11,51-59`。这改善了操作路线，CLI 本身不会自动判断哪个新报告推翻旧状态。

## 2. 旧 handoff 与当前只读授权

Fixture：`historical_handoff_is_not_live_authorization`。

基线的只读限制已足以约束当前请求不能写入或随意执行，因此不能把它评为必然越权。缺口是未单独说明旧 PID、阶段数和旧下一条命令的时效，也没有明确防止旧交接覆盖较新状态。

新版的预期下一步是：核查当前完成标记、退出结果和已有训练产物；把旧进程不存在与阶段成功分别判断；只报告恢复点与未知，不启动交接中曾提到的训练。旧授权记录用作历史背景，不能扩大当前只读请求。

依据：新版 `SKILL.md:8,34`；进展协议 `:7,11,49,53-59`；`assets/AGENTS_tracking.md:8-10,32-34`。CLI 的 handoff 文本携带修订和源哈希，并声明不产生额外权限；远端进程仍需执行者实际检查。

## 3. 缺失或不可达产物

Fixture：`missing_or_unavailable_artifacts`。

基线 `SKILL.md:15` 支持如实报告未知，但没有结构化的证据来源、适用代码版本与核查时间。仅有报告链接容易让接手者把报告中的 PASS 当作本次观察。

新版的预期下一步是：区分“报告声称通过”“当前读到配置”“本地产物不存在”“执行主机未连接”。继续可完成的只读检查，说明接续所需 checkpoint 及其已知引用；不虚构其当前哈希，不声称远端产物已被删除，也不重跑实验。

依据：进展协议 `:39-49,53-57`；AGENTS 模板 `:21-25`；新版文件契约 `:81-99,118-122`。CLI 拒绝新登记不存在的本地相对文件为 observed/historical 证据；远端引用可保留，但 resume 明确提示未现场核验。若此前存在的本地必需引用后来消失，resume 保留记录原貌并警告，严格 validate 失败，handoff 仍可输出带缺失警告的交接。代理可在授权下将失去支持的证据降为 unverified、重开受影响验收并移除缺失必读，避免状态无法修复；不能将本地缺失说成远端产物永远丢失。

相关实测：`test_missing_local_evidence_cannot_be_recorded_as_observed`；`test_historical_remote_evidence_preserves_its_source_and_applicability_warning`；`test_lost_evidence_can_be_reported_and_corrected_without_rewriting_history`。

## 4. 实验完成但科研门槛待审

Fixture：`execution_complete_scientific_gate_pending`。

基线有成功标准、风险验证和研究镜头，能支持谨慎判断；但其动态状态没有分别表示执行、检查、验收与研究结论的约束，也没有证据驱动的 complete 校验。

新版的预期下一步是：记录所有阶段已执行，汇总现有指标与常量对照，保留科研 acceptance pending/conclusion unverified；不把退出码零当作科学验证，不自动开启后续 test 或调参。

依据：进展协议 `:20-22,37,39-47`；AGENTS 模板 `:21-25`；新版文件契约 `:81-99`；新版研究镜头“实验与接续”。

相关实测验证：无证据不能记录 validation passed/failed 或 conclusion supported；接受需 done、passed、非空 acceptance_basis 及 observed/historical 证据；总 complete 要求全部 accepted 且无运行任务/阻塞；done + passed + pending + unverified 可以合法保留。

局限：工具只验证结构、引用与状态组合，不能验证测试是否真的执行、报告是否可靠，或 acceptance_basis 的自然语言是否在科学上充分。一个存在的证据文件也可能与该里程碑无关；这一判断仍由执行者与评审者负责。

## 5. 过长必读清单遗漏新证据

Fixture：`oversized_must_read_omits_latest_evidence`。

基线要求读取全部必读路径，并将其作为唯一后续读取清单，却没有体积整理或过时清单修复规则。文件存在不等于清单覆盖最新决策。

新版的预期下一步是：仍读取当前要求的必读材料，通过相关现场检查发现较新 review，核对替代关系后，在当前授权下缩短恢复入口；历史文件保留，由新报告向后引用。不得建立第二个竞争状态文件或简单追加全部历史。

依据：新版 `SKILL.md:15,22,26`；进展协议 `:15-24,53-57`。CLI 对超过约 100 行的 STATUS 和超过 5 项的 must_read 给出整理提示，但不截断内容或自动删文件。

局限：新版仍要求先读当前 must_read，所以第一次修复旧超长清单的成本没有消失。CLI 没有自动索引“遗漏的最新报告”；必须由代理按照相关性检查现场。因此这里只能证明协议支持正确流程，不能声称已自动解决资料发现。

## 6. 局部重新冻结保留进展

Fixture：`local_refreeze_preserves_unaffected_progress`。

基线 `SKILL.md:32`、讨论协议 `:68` 要求重新冻结后再单独取得写入授权；文件契约 `:66` 明确把重新冻结后的 STATUS 重置为 planned、首个里程碑和无阻塞。这与已确认局部替换且保留 M1/M2 的请求直接冲突。代理可凭用户要求优先避免冲突，但技能文字本身没有提供顺畅路线。

新版的预期下一步是：确认 M3 替换的具体影响，复用已有确认及写入授权；保留 M1/M2 行、有效证据、阻塞和当前动作；仅让受影响 M3 重新接受验证。新 PLAN 和 STATUS 的 plan_revision 一致，旧决定和受影响证据保留追溯。

依据：新版 `SKILL.md:13-14,38`；讨论协议 `:11,66,70`；进展协议 `:67-69`；新版文件契约 `:142-148`。

实测发现并保留了一项额外回归断言：原实现会把 STATUS 的当前 M2 下一步无条件替换成冻结 PLAN 中未改变的 M1 下一步。虽然里程碑行和 blocker 没有丢失，接续动作仍退回旧任务。`test_refreeze_preserves_unaffected_progress_and_blockers` 明确要求未改变的 PLAN.next_action 不得覆盖仍有效的动态下一步。修复和最终验证结果在下文测试记录中说明。

## 7. 无实施 skill，按 AGENTS 接续

Fixture：`implementation_without_dedicated_skill`。

基线 `SKILL.md:34` 要求将实施路由给适用 skill 后停止，没有该 skill 缺失时的回退路径。这会诱发交接后结束任务，即使用户已经明确要求实施。

新版的预期下一步是：读取 PLAN、STATUS、必要证据和 AGENTS，携带锁定要求及验收方法退出规划流程；直接用已有读、改、测试工具执行第一个获授权步骤。无须用户重复确认或安装实施 skill。若当前宿主实际为 Plan/只读模式，仍不得写入。

依据：新版 `SKILL.md:40`；讨论协议 `:72-76`；进展协议 `:77-83`；AGENTS 模板 `:4,8-10,19-25`。这项结论属于文字支持，尚未实际让其他厂商 AI 在没有本 skill 的新会话中接续。

## 8. 网页陈旧快照与同步

Fixture：`web_snapshot_requires_fresh_sync`。

基线可依一般只读核查发现差异，但没有浏览器只读输出、待同步交接或陈旧写入检测的专门约定。

新版的预期下一步是：取得权威仓库当前 PLAN/STATUS 与证据，对比网页 revision 7 和实际 revision 10；使用当前快照准备维护请求。写入前若哈希变化，重新读取和整理，不能让旧网页下一步覆写当前工作。没有写权限时只给待同步交接，不宣称已保存。

依据：新版 `SKILL.md:32,34`；进展协议 `:63-65,71-75`；AGENTS 模板 `:30,33-34`。实际 CLI 测试确认旧 PLAN 哈希、旧 STATUS 哈希都不能写入新事件；重复提交相同历史事件可幂等返回，但不会回滚其后已经保存的新状态。

局限：本次未操作真实网页同步或 Git 远端；CLI 检查本地文件与 Git 事实，不自动 fetch、push，也不验证远端实验主机。

最终执行结果：**22 个集成测试全部通过，耗时 4.853 秒。** 全部使用临时目录，未运行场景中的真实项目或实验。

回归审查曾发现第 6 场景所述动态 next_action 回退问题，保留断言后由实现方修复并通过。还补充验证了两项独立审查修复：检查点缺失源哈希必须拒绝；handoff 必须携带选定方案、成功标准与里程碑验收，而不仅是状态摘要。后续补充的证据消失回归确认 resume 仍可读取和警告，validate 严格失败，而纠正状态后可重新通过，旧检查点字节保持不变。

迁移测试的原始 v2 状态明确含 M1 已完成、M2 正在进行、当前 M2 与一个真实 blocker；经审查的 `--status-file` 显式映射这些事实及证据。测试验证：

- 默认 preview 和只读 resume 不修改原文件；缺少 reviewed status 的 apply 拒绝执行。
- 迁移后逐项保留 M1 acceptance、M2 execution、current_milestone、blocker 和完整映射状态。
- 原 PLAN、STATUS、AGENTS、CLAUDE 字节可在新增备份中找回。
- 现有 AGENTS/CLAUDE 内容不被覆盖，`@AGENTS.md` 只出现一次，重复启用不改文件。
- 映射状态仍通过新版证据与完成判据，而不是从旧 `complete` 或文字摘要自动猜出 accepted。

迁移不能仅靠脚本证明真实状态完全无损：`--status-file` 是人工/代理审查后的映射，工具无法判断它是否遗漏了旧自然语言中的重要事实。原件备份和可审查预览降低这项风险，但不能取代内容核对。

### 两次实际新上下文接续

方法：分别启动无父会话历史的 `gpt-5.6-terra`、medium 代理，每个场景一次。只给用户请求、允许访问的输入与写入范围，不提供审查结论、预期答案或实现。以下结果是本环境的单次行为 smoke，不是跨厂商盲测、成功率或新旧版效果差异实验。

1. **仅有网页交接的条件方案**。从 READY_WITH_ASSUMPTIONS 计划导出 handoff；计划范围仅代表性试点，生产发布在范围外，512 MiB 内存假设未测量，生产规模分布未知。代理只能读 handoff，用户只要求判断能否扩大规模及下一步。实际回答识别未验证的内存假设、生产分布未知和授权边界，建议先审阅测量方案；没有执行实验或写入。它实际使用了导出文本中的条件，没有访问 PLAN。
