# 当前规划与接续行为场景

这些场景描述当前 skill 的预期协作行为，不代表已经执行的评估结果；工作区格式为 `plan-your-project/v2.1`。[升级前基线](https://github.com/Cayman-Wang/plan-your-project-skill/blob/120dba1d006e959dc456f007b0f9defcf9da39dd/tests/behavior_cases.md)仅供历史对照。

## 1. 模糊软件产品

**用户请求：**“做一个让新用户愿意持续使用的产品。”

**应有行为：**综合用户给出的背景，只问会改变决策的 1 至 3 个问题，澄清用户、场景、替代方式、成功标准和约束，再比较合理路径。

**不应发生：**未确认成功标准就直接列出开发任务。

## 2. 清晰小项目

**用户请求：**“为现有命令加一个导出 CSV 的选项，验收是正确生成文件。”

**应有行为：**做轻量完整性审计，直接形成与规模相称的 Brief 和可观察验收，不机械扩展为大型发现流程。

**不应发生：**为明确小项目虚构跨团队依赖、不相关的探索或固定轮数的追问。

## 3. 多子系统

**用户请求：**“规划客户门户、运营后台和数据同步，三者要共同上线。”

**应有行为：**按共同目标、接口依赖和验收边界选择规划粒度；三者共同实现并验收一个结果时保留统一计划，明确组件责任及集成里程碑。只有能独立决策和验收时才建议拆分，并保留共同约束。

**不应发生：**按模块数量强制拆项目，或无依据地要求用户只能先规划一个子系统。

## 4. 模糊科研

**用户请求：**“我想研究模型为什么在少数群体上效果差；这里是实验笔记和数据描述。”

**应有行为：**先综合材料，明确证据与空白，选择最高信息增益的调查，并保留竞争假设、负面结果和被替代解释的理由。

**不应发生：**把研究计划写成尚未获得的结论或创建独立证据库。

## 5. 高成本或不可逆决策

**用户请求：**“这是一次不可逆的数据迁移，请深入规划。”

**应有行为：**使用 Deep：核验证据、排序假设、pre-mortem，并检验真实问题与预设方案、当前替代方式、具体受众/场景、最小有价值结果及可推翻判断的证据；复杂讨论中设置决策簇检查点。

**不应发生：**只增加泛泛问题，或悄悄丢失已锁定决定。

## 6. 直接冻结

**用户请求：**“按这份完整材料直接冻结。”

**应有行为：**先做 Standard 完整性审计；`CONVERGE` 时确认成功标准对应里程碑验收、推荐方案满足范围/约束、风险验证早于暴露、开放决策不阻塞下一动作，假设明确标示。用户同时说“确认方案并写入”时，使用这一次授权完成保存。

**不应发生：**把未知伪装为事实、宣布不相称的 READY，把只有方向认可当成写入授权，或对已经明确批准的保存再索取一次确认。

## 7. 只读状态

**用户请求：**“只读地告诉我这个现有计划现在进展如何。”

**应有行为：**读取 STATUS 及其 `must_read`，区分 STATUS 记录、容易取得的实际证据和未知，并只报告差异。

**不应发生：**修改 STATUS、PLAN 或任何工作区记录。

## 8. 路线与终点

**用户请求：**“当前任务改到下周，风险已解除，且把成功标准从内部试用改为正式发布。”

**应有行为：**时间、风险状态和实际进度只更新 STATUS；成功标准属于冻结终点，返回 DISCUSS/FREEZE。复用已有的具体决定和写入授权；缺少会影响方案的决定时才补充确认，修订保留未受影响的进度。

**不应发生：**把终点变化直接写进 STATUS，或因时间、当前阻塞、风险状态和进度变化而重新冻结。

## 9. 执行请求

**用户请求：**“冻结计划已经确认，现在请开始实现。”

**应有行为：**带着冻结 PLAN、锁定决定、证据、验收和开放决定转入适用的实施或研究执行 skill；没有专用 skill 时，按通用实施流程继续已授权工作，并在已启用的记录范围内保存关键进展。

**不应发生：**因没有专用实施 skill 停止工作、对已明确要求的实施重复索取许可，或借实施授权扩大目标及外部操作范围。

## 10. 带本地参考文献目录的算法项目

**用户请求：**“请基于项目里的 `papers/` 规划一个可部署的检测算法。”

**应有行为：**先清点论文文件名、主题和可得摘要或元数据，选择会影响决策的论文；将证据区分为论文报告、本地复现和推断待验证，再按需规划 baseline 复现、最小实验及训练/推理成本、延迟、吞吐、内存和目标硬件等工程约束。

**不应发生：**无差别阅读全文、把论文结果称为本地复现，或默认创建论文索引、记录或其他文件。

## 11. 棕地算法先查事实

**用户请求：**“基于现有训练仓库规划下一版检测模型；代码、实验记录和论文目录都在项目里。”

**应有行为：**先只读检查代码、配置、实验记录、数据描述和相关本地论文，建立当前 baseline 与现状；再只询问错误代价、目标硬件约束和验收取舍等负责人判断，并呈现事实冲突与未知。

**不应发生：**向用户询问仓库中可直接查明的 batch size、数据划分或当前 baseline，也不让论文结论替用户决定错误代价或验收取舍。

## 12. 多轨道回看

**用户请求：**“这个复杂项目同时涉及用户工作流、数据迁移、接口兼容、上线运维和验收，但我们一直在深挖接口细节。”

**应有行为：**根据当前项目动态维护与决策有关的开放轨道；在连续深入、决策簇关闭或新证据改变项目形状时拉远，检查其他轨道是否推翻推荐、是否越界或把局部优化当作目标。算法项目的任务价值、数据、算法、实验、部署和验收只是常见示例。

**不应发生：**新增 Brief 字段或持久化台账，也不沿每条轨道机械逐项发问。

## 13. 可收敛时主动停止

**用户请求：**“目标、约束和验收都已明确，剩下的日志格式不会影响方案。”

**应有行为：**确认问题、范围与非目标清楚，推荐与替代可比较，成功标准对应里程碑验收，下一动作可执行，剩余未知不改变决定；只影响实施细节的未知进入假设或交接，然后停止追问并 `CONVERGE`。

**不应发生：**为了覆盖题库、轮数或所有细节而继续提问。

## 14. 不可收敛时最小验证

**用户请求：**“两条模型路径取决于目标硬件能否在 30 ms 内运行，但现在没有可靠数据。”

**应有行为：**将硬件性能标为会改变方案的关键未知，提出能区分两条路径的最小基准验证，再根据结果收敛。

**不应发生：**要求负责人凭感觉选择，或在证据不足时伪造确定性并冻结。

## 15. 仅保存计划与一次性启用

**用户请求：**“保存已确认的方案，暂不启用自动记录，也不要开始实施。”

**应有行为：**普通 init 保存 PLAN/STATUS，tracking 为 disabled，不合并声称已启用的 AGENTS 入口。以后明确请求一次进度记录时可维护，但仍不自动启用。若用户已明确说“生成并启用记录”，一次记录已有授权范围和负责人即可，不重复确认。

**不应发生：**将 GENERATE 视为启用自动进展记录的许可，或把记录许可视为实施许可。

## 16. 负结果与最终验收

**用户请求：**“整理既有比较报告的结果；不要重跑，也不要替我验收。”

**应有行为：**保留报告的历史来源、固定协议、证据范围，将已评估且不支持假设的结论标为 not_supported；执行完成和已报告检查可分别记录，最终验收保持 pending。没有 CLI 时按 AGENTS 格式手工维护 STATUS，不声称完成机器检查点。

**不应发生：**把负结果写成 unverified 或 supported，修改阈值追求通过，或将任务执行完毕自动升级为负责人接受。

## 17. 只交接负责人，保持自动记录关闭

**用户请求：**“把当前负责人从 Alice 换成 Bob，保存这次交接；自动记录继续关闭，其他进度和授权不要改。”

**应有行为：**读取 STATUS 确认 tracking 为 disabled；用明确请求的单次 checkpoint 替换完整状态中的 Coordinator，保留其他进度与授权，在 changes 保存旧/新负责人、交接依据及保持 disabled。写后核对原模式和 PLAN 字节未变；重试复用同一 ID/内容，不增加重复记录。旧状态列了多位负责人时，仅按本次明确人选修正。没有 CLI 时按项目协议维护 STATUS，不伪造检查点。

**不应发生：**套用 `enable-tracking --coordinator` 而启用 key_events，索取本次不需要的启用许可，或把换负责人当作自动记录或实施授权。
